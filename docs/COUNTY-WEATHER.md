# 区县天气与自动定位

设置 → 现实中的天空，依次选择省／自治区／直辖市、城市／地区、区／县／县级市。目录包含 34 个省级地区、392 个市级目录、3212 个区县条目，包括直辖市、自治县及县级市。直筒子市、特别行政区按数据源的兼容层级显示，目录 ID 不全部等同于六位国标代码。行政区划是版本化快照，后续区划变更可重建数据包。

手动选择使用所选区县内部的 WGS84 坐标。源数据中心不在县域内的，改用县域内部代表点，避免政府驻地在相邻市区时误用市中心天气。天气请求保留六位小数，缓存以区县代码区分；同名“鼓楼区”等不会混用。Open-Meteo 提供该坐标附近的网格天气，区县级地点选择不等于每个区县都有独立气象站实测。

自动模式在启动时进行一次定位，设置和托盘的“自动定位”可重新请求。优先调用 Windows 高精度定位，最多等待约 22 秒；无有效结果或无法确认区县时，再尝试 IP 定位。IP 服务依次为 https://ipwho.is/ 与 https://ipapi.co/json/，HTTPS、每个请求超时 8 秒，无需 API Key。只读取返回的国家与经纬度，不持久化 IP 地址，也不把系统定位坐标发给 IP 服务。服务会看到连接的出口 IP；代理和运营商出口可能造成偏差。

系统定位结果必须在 5 分钟内有效，其水平误差范围与约 20 米的边界保护带应落在同一区县内，否则进入 IP 回退。IP 坐标同样通过本地边界匹配，但明确标注“IP 估算”，不宣称区县精度或虚构误差半径。无效、过期、国外或无法匹配的 IP 结果视为失败。两个 IP 服务都失败后使用默认北京（东城区），界面提示手选。初次启动也以北京为默认地点。

自动模式天气使用实际系统坐标或 IP 返回坐标；手动模式使用所选区县内部坐标。界面区分系统定位、IP 估算、默认地点与手动区县。手选会退出自动模式并跨重启保存；旧请求的结果或失败通知都不能覆盖手选。点击自动定位可再次启用自动模式。不持续跟踪，不逐帧查询，不影响农场、画质、音量或镜头。

## 数据与构建

- 目录与主要边界来自 AreaCity 2025.251231.260403（2026-04-03）。台湾乡镇区边界由 Taiwan-GeoJSON 补齐；近期新增和康县、和安县、岑岭县由 OpenStreetMap 行政边界补充，并从旧辖区中扣除重叠范围。
- data/china_regions.json 保存层级、名称、区县天气坐标及边界索引。data/regions/*.bin 按省保存 GCJ-02 边界，定位点在本地转换后判定；天气请求使用 WGS84，避免直接混用两种坐标系。
- 边界约 31 MB，只在请求定位时按索引读取候选县的多边形，不常驻加载全国顶点，也不逐帧做地理查询。
- 来源、校验和授权见 data/regions-source.json、docs/third-party/REGION-DATA.txt。dev/build_regions.py 从归档输入重建，依赖只用于开发，不进入运行包。
