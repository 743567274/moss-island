# 便携版作物现实性核查

核查对象：2026-10-26 的 Windows x64 便携版、`build/crops`、初始自定义玫瑰包与对应生长/编辑器源码。八个基础作物配置与ZIP内文件一致。仅作静态审查与资料对照，没有运行功能测试，也没有更改作物、存档或发布包。

## 结论

当前版本是“真实时间推进的简化种植模拟”，还不能称为完整现实生长模型。问题既包括程序兼容缺陷，也包括此前选择的单次采收玩法与真实植物习性的差异。不能只把总天数改长或改短就解决。

## 1. 优先修复：编辑器会丢失旧包的生长阶段

`scripts/farm/crop_editor_store.gd` 的 `slots()` 按图片名称匹配阶段，而且遇到第一个匹配就停止；`save()` 对普通作物只重建种子、幼苗、半成熟、成熟四个阶段，前三段累计决定成熟时间。

旧包却存在开花、结铃、膨果、灌浆、越冬等多个独立阶段，其中可能共用同一张图片。这些阶段不是多余数据，不能因为只有12张视觉状态图而删除。

| 植物 | 发布包当前到成熟天数 | 按现有编辑器映射再保存的潜在天数 |
|---|---:|---:|
| 玉米 | 120 | 42 |
| 棉花 | 160 | 63 |
| 辣椒 | 150 | 86 |
| 西红柿 | 130 | 70 |
| 烟叶 | 180 | 120 |
| 春小麦 | 120 | 60 |
| 冬小麦 | 250 | 80 |
| 玫瑰 | 120 | 120 |

这些数字是静态按代码计算的保存结果，不代表发布包一启动就已经缩短了周期。玉米还会缺少半成熟缺水/死亡两个状态映射；用户需补齐图片才能继续保存。有种植或库存引用时，总周期保护规则也会阻止改动，所以不是所有情况下都会实际保存成功。

其他兼容问题：

- 阶段专用温度没有完整读回，可能被全局温度覆盖。
- `maxf(1, ...)` 会把不足一天的阶段读成至少一天。
- 玉米旧资产名 `adult_dry` / `adult_dead` 没有被半成熟对应槽位正确兼容。
- 视觉状态、农艺阶段、可编辑参数三个概念混在一起。

建议将“12个图片槽位”与“任意多个生长阶段”分开保存。打开后不修改参数就保存，应保留原阶段、总时间、温度和耗水；不应通过固定三段重新猜测原配置。

## 2. 生长适温与致死温度混用

当前温度系统只有一套适温上下限。落在范围外会按统一规则减速/停止，并累计温度伤害；玉米等多数配置达到48小时死亡，棉花为36小时。

现实中，发芽最低温、最适温、最低生长温、寒害温、冻死温、高温授粉障碍并不是同一阈值。气象气温也不等同于种子所在土层温度。

例如[新罕布什尔大学甜玉米资料](https://extension.unh.edu/resource/growing-sweet-corn-fact-sheet)将土温发芽条件与幼苗轻霜耐受分开说明。不能据此设置为“气温一低于当前适温下限，固定两天就枯死”。

建议：将成长温区、渐进胁迫与危险/致死温区分开；种子萌发用土温近似或明确标注气温近似。保留品种、阶段和持续时间差异。

## 3. 作物时长应有品种、起算点和采收目标

| 植物 | 当前参数 | 核查意见 |
|---|---|---|
| 玉米 | 播种至成熟120天，每田1株，收4穗 | 120天不是通用错误，但必须区分甜玉米鲜穗与籽粒成熟；一株固定4穗偏高，不能把原多株田块的产量直接用于单株。 |
| 棉花 | 160天 | 可落在某些栽培条件的合理范围，但只是参考周期，缺少积温与分批吐絮/采摘过程。 |
| 春小麦 | 120天 | 可作特定模板，不能涵盖不同品种、地区与气候。 |
| 冬小麦 | 250天 | 长度可以作为秋播次年收的模板，但缺少真正春化条件与越冬生长速率，固定105天越冬不等于模拟春化。 |
| 西红柿 | 130天，单次采收 | 需要区分从种子还是从移栽起算；不同生长习性的番茄有不同采收窗口，采一批后整株枯萎不通用。 |
| 辣椒 | 150天，单次采收 | 需要品种与青果/红果目标；很多类型分批采果，不是一次采完必然枯死。 |
| 烟叶 | 180天，整株统一成熟 | 需区分烟草类型、育苗/移栽与采叶方法；不同类型可整株收，也可分叶位采收，不能默认统一采法。 |
| 玫瑰 | 种子28天、幼苗62天、现蕾30天，120天收花后枯萎 | 没有冷湿层积、品种差异与多年生恢复；不能作为所有玫瑰种播规律。 |

资料依据：

- [明尼苏达大学甜玉米品种表](https://extension.umn.edu/garden-and-home/yard-and-garden/gardening-in-minnesota/growing-sweet-corn)：不同甜玉米品种成熟天数不同。
- [伊利诺伊大学玉米种植](https://extension.illinois.edu/gardening/corn)：条件良好时很多品种可以结第二穗，不支持把每株4穗当通用现实默认值。
- [Cotton SA技术资料](https://cottonsa.org.za/technical-information/)：约160～180天取决于品种、产区与热量条件，并区分开花、成铃和吐絮。
- [FAO作物水分产量资料](https://www.fao.org/4/i2800e/i2800e.pdf)：小麦发育与春化需求、光周期和温度有关。
- [明尼苏达大学蔬菜种植计划资料](https://extension.umn.edu/agriculture/specialty-crops/vegetable-farming/crop-and-field-planning-tools-for-vegetable-farmers)：区分播种至移栽、移栽至首次采收与采收窗口。
- [Rutgers辣椒生产资料](https://extension.rutgers.edu/fs1273)：所述辣椒类型在生长季多次采收；不能据此推定所有辣椒具有同一个次数和间隔。
- [爱荷华州立大学玫瑰繁殖](https://yardandgarden.extension.iastate.edu/how-to/how-propagate-roses)：很多玫瑰种子需冷处理，部分还需先暖处理，不能统一28天直接发芽。
- [佐治亚大学烟草生产指南](https://tobacco.caes.uga.edu/content/dam/caes-subsite/tobacco/docs/growers-guide/2013/2013-Georgia-tobacco-growers-guide.pdf)与[肯塔基大学白肋烟采收](https://burleytobaccoextension.mgcafe.uky.edu/harvest)：采收制度依烟草类型而异。

## 4. 浇水是水量模型，但不是完整现实灌溉模型

目前有储水容量、每次补水量、阶段日耗水、缺水预警和干土死亡等待，已经不是纯粹“每几小时点一下”的倒计时。

但日耗水基本按阶段固定，没有根据蒸散、太阳辐射、空气湿度、土壤类型、根深和阶段胁迫改变。风主要用于画面运动，不等于参与蒸散计算。不同植物又共用大量水量默认值，不能说完全符合现实。

[FAO作物需水资料](https://www.fao.org/4/s2022e/s2022e02.htm)明确区分气候、作物类型和生长阶段对需水量的影响。其季节需水范围也不能直接等同于“每次点击浇多少水”。

当前所有基础包的初始水量都为0，因此一播种就可能缺水。这是配置选择，不是软件漏包。若要更自然，应定义“播入湿土”或“播后浇透”的流程。

此外，当前没有区分未吸水干种子与已萌发种子。将所有播种后缺水都统一计为数天后种子死亡不够真实；[种子保存资料](https://extension.umn.edu/garden-and-home/yard-and-garden/gardening-in-minnesota/saving-vegetable-seeds)支持凉爽干燥条件下保存种子，但保存状态与湿土播种后环境也不能简单混为一谈。

## 5. 当前是按真实秒推进，不是完整气候生长模型

水分足、温度在范围内时，当前主要按经过的秒数增加成长；不同适温之间没有细致的生长速率差异。没有完整积温、光周期、春化和历史天气回算。

离线时不会伪造整段历史温度或降雨，这个限制应保留并明确说明。要提高现实性，需要有历史天气或明确的离线近似策略，而不是把现在一次天气观测套用到所有离线日期。

## 建议修复顺序

1. 先修复编辑器读写兼容，保证不改动参数也不会丢阶段、改周期。
2. 分离视觉状态、农艺阶段与采收模式；不需要增加状态图片数量，就能保留更多生长阶段。
3. 分开适温与危险温区，避免不适温即固定倒计时死亡。
4. 按品种/用途设置成熟目标与产量，确认哪些植物应单次、分批或重复采收。
5. 再补冬小麦春化、玫瑰种子处理及气候相关用水。缺乏物种/品种依据的数值继续标记为模拟参数。

本轮不改发布包和旧存档。此前用户已经确定过“作物单次采收”的玩法，因此重复采收属于规则调整，应明确区分它与必须修复的编辑器数据丢失缺陷。
